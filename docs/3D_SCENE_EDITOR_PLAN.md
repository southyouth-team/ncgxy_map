# 三维校园场景编辑器实施方案

## 1. 产品定义

三维校园场景编辑器面向没有 GIS、CAD、Blender 建模经验的校园运营人员。最终产物是可浏览、可导航的三维校园；编辑过程采用接近 PPT / 搭积木的低门槛交互。

核心原则：**二维方式操作，三维结果呈现；模板优先，模块补充；业务对象优先于网格编辑。**

## 2. 编辑体验

### 工作区布局
- 左侧：素材库，按建筑、道路、地面、水体、植被、校园设施分类。
- 中央：Three.js 三维画布，支持俯视/等距/自由观察。
- 右侧：属性面板，展示选中对象的名称、分类、位置、尺寸、旋转、高度、楼层、外观等可编辑属性。
- 顶部：选择、移动、旋转、缩放、复制、删除、撤销、重做、保存、预览。

### 新建对象的两种入口（混合模式）
1. 模板拖放：完整教学楼、宿舍楼、食堂、图书馆等 GLB 模型或参数化建筑模板，拖入画布后调整占地、楼层和外观。
2. 积木组合：在高级入口中使用楼层模块、主体、屋顶、门窗等组件组合建筑；组合后仍作为一个 Building 业务对象管理。

默认路径必须是模板拖放，不要求普通用户接触模块细节。

### 场景对象类型
- Building：建筑，支持模板/模块来源、占地尺寸、楼层数、层高、总高度、外观。
- Road：道路，使用可编辑中心线路径、宽度和路面样式生成三维路面。
- Terrain：草地、广场、操场等地表区域。
- Water：湖泊、水池、河道等水域。
- Vegetation：树木、灌木、绿化组团。
- Facility：路灯、座椅、雕塑、指示牌、停车棚等设施。

## 3. 交互标准
- 平面拖动优先：在地面 XZ 平面移动对象，默认吸附网格，可临时关闭吸附。
- 变换手柄：提供移动、旋转、缩放；普通模式不暴露三维坐标轴细节。
- 建筑参数化：通过楼层步进器、尺寸输入和滑块调整建筑，不直接编辑顶点。
- 道路绘制：点击/拖动添加路径点，自动生成圆滑路面；支持调整宽度和节点。
- 地表绘制：画多边形区域并选择材质类型。
- 快捷操作：复制、删除、撤销/重做、多选、对齐、等距分布、图层锁定/隐藏。
- 视角：俯视编辑、等距编辑、自由预览；编辑时优先保持俯视或等距，避免透视操作误差。

## 4. 场景数据与渲染分层
- Scene JSON 是编辑器的规范化持久化格式，存储对象 ID、type、templateId、transform、业务 properties、layerId 和 schemaVersion。
- Scene Document 与 Three.js Object3D 分离；Three.js 对象是可重建的渲染结果，不作为唯一数据源。
- 每种对象由独立 factory 从 Scene Object 生成 Three.js Object3D。
- GLB 是模板资产格式；模板元数据独立于具体场景实例。
- campus-local 坐标继续作为校园局部坐标。Three.js 地面映射为 XZ，Y 表示高度；当前示意比例不能冒充真实米制测绘。
- 现有 PostGIS Feature/Layer/Asset 保留给空间数据与资产管理；三维 Scene Document 先独立版本化，后续再设计 API 持久化，不将二维 Polygon 强行当作完整三维对象。

## 5. 分阶段交付

### P0：架构基线与数据契约
- 明确 Scene Document、Scene Object、模板目录和对象类型。
- 编写纯数据层及单元测试。
- 暂停把仿射配准作为主编辑入口；保留为底图校准高级工具。

### P1：可用编辑器 MVP
- 建立三栏编辑器工作区。
- Three.js 编辑视口与场景对象同步。
- 模板拖入、选择、移动、旋转、缩放、复制、删除。
- 建筑模板支持楼层、占地和高度参数。
- 撤销/重做、网格吸附、本地草稿保存/恢复。

### P2：校园环境编辑
- 道路路径绘制与宽度调整。
- 草地/广场/操场多边形绘制。
- 湖泊水域、树木和设施素材。
- 图层、分组、锁定、隐藏、对齐。

### P3：业务数据与发布
- Scene Document 服务端持久化、revision 乐观锁和历史版本。
- 真实建筑清单与场景对象绑定。
- 场景发布、只读预览和运行时地图加载。

### P4：高级积木建模
- 建筑模块拆分/组合、模块库、组合模板保存。
- 不把专业网格建模、UV、骨骼动画等纳入普通编辑路径。

## 6. MVP 验收标准
1. 新用户无需阅读建模教程，能在 10 分钟内搭出包含 3 栋建筑、道路、绿地和水体的简单场景。
2. 可从模板库拖入建筑并调整位置、旋转、占地和楼层。
3. 可通过高级入口组合基础建筑模块，组合体仍可整体移动和编辑。
4. 所有编辑操作可撤销/重做。
5. 保存并刷新后场景可恢复，且业务属性不丢失。
6. 浏览模式继续支持现有上帝视角、第三人称和第一人称漫游。
7. 未核实的建筑名称、楼层和尺寸必须标记为待核实，不得把演示数据表述为测绘事实。

## 7. 当前代码调整原则
- 延续 Vue 3 + Three.js，不引入第二套渲染引擎。
- 将现有硬编码场景逐步迁移为 Scene Document + factories，不一次性推翻漫游引擎。
- 先做数据契约和独立编辑模块，再接入 UI 与 API。
- 旧二维地图编辑器保留为底图/矢量数据校准工具，不再作为三维场景搭建的主入口。
