# 校园空间矢量化作业规范 V1.0

## 目标

把 2026 新生指南校园平面图逐步转换为可核验的校园空间数据。当前 V2 数据模型尚未接入生产三维场景；本规范用于约束人工数字化过程，避免将旧版演示坐标误迁移为真实数据。

## 坐标约定

- 原点：参考图片左上角。
- X 轴：向右；Y 轴：向下。
- 单位：原始图片像素（px）。
- 所有几何必须落在参考图片宽高范围内。
- 图片必须保留原始宽高和来源 ID。不得先截图缩放再沿用原始像素坐标。
- 在没有可靠控制点和比例尺前，不将像素坐标称为米、经纬度或测绘坐标。

## 要素几何

V2 使用 GeoJSON 风格的 geometry：

| 要素 | geometry.type | 说明 |
|---|---|---|
| 出入口、地标 | Point | 单个像素坐标 [x, y] |
| 道路中心线、桥梁轴线 | LineString | 至少两个连续坐标点 |
| 校园边界、湖泊、运动场、建筑、绿地 | Polygon | 至少一个闭合环，首尾坐标必须相同 |

Polygon 坐标环必须闭合；禁止用矩形包围盒代替明显不规则的真实轮廓。道路优先记录中心线，后续再根据道路宽度生成可视化面。

## 每个要素的必填元数据

```js
{
  id: 'building-library-01',
  type: 'building',
  name: '待核验名称',
  status: 'draft',
  confidence: 'medium',
  sourceRefs: ['freshman-guide-2026-campus-plan'],
  geometry: {
    type: 'Polygon',
    coordinates: [[[x1, y1], [x2, y2], [x3, y3], [x1, y1]]]
  },
  properties: {
    function: 'unknown',
    floors: null,
    notes: '名称、楼层待官方资料或现场核验'
  }
}
```

- `id`：稳定且唯一，创建后不因名称修订而改变。
- `type`：采用要素类别，不把展示名称当作类型。
- `status`：`unverified`（未核验）、`draft`（已初步描绘）、`verified`（已核验）。
- `confidence`：`low`、`medium`、`high`，表达当前几何/识别可信度。
- `sourceRefs`：至少一个来源 ID；官方照片、指南地图、现场核验分别登记来源。
- `properties`：只存有来源依据的属性；未知值使用 null 或 unknown，不猜测。

## 标注顺序

1. 校园外边界和出入口。
2. 主干道路与主要交叉口。
3. 湖泊、岸线和桥梁。
4. 体育场、运动场。
5. 建筑组团范围。
6. 建筑逐栋 footprint。
7. 绿地和景观节点。

先标注大尺度骨架，再拆建筑；不要先堆大量建筑模型。

## 复核规则

- 第一人完成初稿后，第二人对照原图独立复核关键拐点和拓扑关系。
- 交叉口必须与道路连通；桥梁应连接两侧可通行区域。
- 湖泊、运动场、建筑 footprint 不应无依据地互相覆盖。
- 建筑组团只是组织信息，不能替代单栋建筑 footprint。
- 重点地标名称必须能关联官方网页、官方照片或现场证据。
- 无法辨认的建筑保留临时 ID，不得猜楼名。
- 每次批量导入前运行几何校验，并抽样检查原图叠加效果。

## 当前工具状态与限制

- `src/data/campus/campusLayoutV2.js` 已提供坐标转换、校准参数校验、要素元数据校验和 Point/LineString/Polygon 几何边界校验。
- `src/editor/CampusPlanEditor.vue` 仍主要编辑旧版 640×480 数据结构；其参考图与控制点能力不能视为 V2 已完成接入。
- 在 V2 适配层和数据迁移审查完成前，不要直接把编辑器保存结果写入 `CAMPUS_LAYOUT_V2`。
- 不将受版权保护的参考图片或其插画内容直接作为公开项目贴图；只记录来源和数字化成果。
