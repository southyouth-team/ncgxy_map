# 南昌工学院三维校园地图美术风格规范 V1.0

## 1. 风格决策

项目统一采用 **等距视角 2.5D 像素艺术（Isometric Pixel Art）**，以用户提供的校园像素地图参考图作为美术方向基准。

这不是静态 2D 地图，也不是纯 Minecraft/Voxel 风格。场景必须保留真实三维空间、建筑体块和可交互对象，通过低分辨率纹理、像素化细节、清晰轮廓线和等距构图形成统一视觉语言。

## 2. 视觉原则

1. **空间真实优先**：道路走向、建筑 footprint、建筑相对位置和体量比例必须来自底图或现场核验数据，不能为了构图随意移动真实建筑。
2. **风格统一**：建筑、道路、植被、路灯、车辆、人物和 UI 使用同一套像素艺术规范。
3. **轮廓清晰**：建筑主体边缘、屋顶转折和主要结构使用清晰深色轮廓；避免过度描边导致画面脏乱。
4. **细节分级**：远景优先识别建筑体量和屋顶轮廓；近景再显示窗户、入口、檐口和装饰。
5. **可读性优先**：建筑名称、道路和交互热点不能被装饰物遮挡；地图缩小时自动降低细节密度。
6. **不混搭**：避免写实 PBR、Minecraft 方块堆叠、扁平 2D 图标和普通低多边形资产直接混用。

## 3. 场景资产规范

| 资产类别 | 推荐实现 | 必须保留的信息 |
|---|---|---|
| 普通教学楼/宿舍楼 | 程序化 3D 体块 + 像素化立面 | footprint、层数、体量、屋顶轮廓 |
| 标志性建筑 | 独立低模/简化 GLB | 可辨识外形、主要入口、特殊结构 |
| 道路/广场/人行道 | 根据真实道路矢量数据程序化生成 | 道路走向、宽度关系、交叉口 |
| 草坪/绿化带 | 简化地形面 + 像素纹理 | 绿化区域边界 |
| 树木/灌木/花坛 | 可复用低模或像素 Sprite | 大致位置、树冠尺度层级 |
| 路灯/长椅/标识 | 模块化小型资产 | 位置和基本轮廓 |
| 人物/车辆 | 2D Sprite 或风格化低模 | 作为场景氛围，不得遮挡主要建筑 |

普通楼栋优先程序化生成，不要求每栋都人工制作完整 GLB。重点建筑可以使用独立模型补充独特造型。

## 4. 相机与构图

- 默认地图浏览模式采用正交相机（Orthographic Camera）和等距视角。
- 默认视角应能识别校园整体布局，并支持平移、缩放和点击建筑。
- 放大后逐级显示建筑立面、窗户、入口和环境细节。
- 第三人称漫游继续使用真实 3D 场景和跟随相机。
- 第一人称模式如保留，应切换为透视相机；不得把等距截图或平面贴图伪装成可漫游场景。
- 模式切换应平滑，且不同相机控制器不得同时响应输入。

## 5. 像素渲染与材质建议

- 使用有限且统一的色板，建筑主色以暖灰、砖红、米白等自然建筑色为主；植被采用分层绿色；道路采用中性灰。
- 纹理使用低分辨率图集，采样采用 nearest-neighbor（最近邻）过滤，避免双线性插值造成模糊。
- 可评估低分辨率 RenderTarget 后整数倍放大，以获得稳定像素颗粒；需测试文字、细线和 UI 的可读性。
- 轮廓效果优先用于建筑主体和关键资产，可采用几何边线或专用轮廓 pass；避免给所有小物件叠加粗黑边。
- 阴影保持块面化、方向统一，不追求写实全局光照。
- 像素化处理应与 UI 分层，UI 文字和交互控件保持清晰，不强制像素化。

## 6. 建筑数据与美术表现分离

建筑的真实空间数据与视觉风格必须解耦：

- 数据层负责 buildingId、名称、位置、footprint、楼层、高度、朝向和来源可信度。
- 生成层根据数据创建建筑几何体。
- 表现层负责材质、色板、像素纹理、轮廓和细节等级。
- 特殊建筑可通过 GLB 覆盖默认程序化模型，但仍应关联同一 buildingId 和空间定位数据。

不得在美术模型中硬编码未经核验的校园坐标或尺寸。当前资产台账中的候选名称不等于已核实建筑实体。

## 7. LOD 分级

| 等级 | 显示内容 | 使用场景 |
|---|---|---|
| LOD0 | 建筑 footprint 色块或简化轮廓 | 全校远景 |
| LOD1 | 主体体块、屋顶、主色块 | 常规地图浏览 |
| LOD2 | 窗户、入口、檐口和主要立面结构 | 局部放大 |
| LOD3 | 标志性构件、特殊屋顶和精细装饰 | 重点建筑近景 |

LOD 切换应避免明显跳变；建筑名称和点击热点应独立于几何细节等级。

## 8. 工程实施约束

- 保持 Vue 3 + Vite + Three.js + JavaScript 技术栈。
- 保留现有场景引擎、建筑数据加载和 GLB 加载扩展点。
- 新增风格材质、像素纹理、轮廓和 LOD 时按模块拆分，不将全部逻辑塞入 App.vue。
- 先做一个可验证的风格样板区，再扩展全校；样板区应至少包含一栋教学楼、一段道路、绿化、路灯和人物 Sprite。
- 样板区验收通过后再批量生产资产，避免全校返工。

## 9. 验收标准

- 等距视角下具有参考图的像素艺术观感，轮廓清晰、色彩统一。
- 建筑位置、道路关系和占地轮廓与核验底图一致。
- 普通建筑可通过数据参数生成，不依赖逐栋手工建模。
- 重点建筑可独立替换模型，不影响数据 ID 和交互逻辑。
- 放大/缩小后 LOD 表现稳定，画面无明显纹理模糊或闪烁。
- 上帝视角、第三人称及第一人称（若保留）使用同一份真实三维场景数据。
- 不以风格化为理由虚构建筑、道路或校园设施。

## 10. 当前阶段范围

本规范确定的是项目美术方向和工程约束，不代表像素风渲染器、资产库或全校建筑模型已经实现。下一步应先制作局部样板场景并进行视觉验收。
