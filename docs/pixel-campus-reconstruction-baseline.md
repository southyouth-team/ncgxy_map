# 南昌工学院像素校园重建基准 V1.0

## 1. 本阶段目标

本项目当前主线收敛为：还原一张可探索的南昌工学院等距像素校园。

交付重点是校园本身，而不是通用 GIS 编辑器或通用三维沙盒。地图布局、建筑、道路、水体、运动场和绿化必须围绕南昌工学院真实校园组织；像素美术负责表达，不得反过来改变真实空间关系。

## 3. 资料使用与真实性约束

1. 平面图负责空间关系，手绘图负责像素美术参考，官方建筑照片负责外观识别，现场采集负责最终核验。
2. 不将任何一张宣传图直接作为最终地图贴图，也不把图中插画建筑直接作为真实建筑模型。
3. 参考图片仅用于项目内部分析和数字化重建；未经权利人许可，不将原图或其插画资产直接打包、公开再分发。
4. 参考图没有可靠比例尺和控制点。完成配准前，坐标只能称为 image/pixel 坐标，不能称为米制坐标。
5. 对名称、轮廓、位置不确定的对象保留临时 ID 和 confidence，不得凭印象补齐精确数据。

## 4. 校园要素重建范围

按以下顺序建立统一空间底稿：

1. 校园外边界、北向和主要出入口。
2. 主干道路、环路、步行道路和关键交叉口。
3. 望月湖及其他可辨识水体、桥梁和岸线。
4. 体育场、运动场、操场和大型活动场地。
5. 全部可辨识建筑 footprint，逐栋编号；建筑群必须拆分为独立物理楼栋。
6. 草坪、林地、绿化带、花坛和重要景观节点。
7. 校园家具、路灯、标识等装饰性资产。

首轮只要求形成全校空间骨架，不急于为每栋楼制作高细节模型。

## 5. 像素校园场景交付顺序

### M1：可信校园平面底稿
- 导入并记录参考图元数据。
- 建立独立的底图坐标系和版本。
- 矢量化边界、道路、水体、运动场、建筑组团。
- 建立要素来源、置信度和待核验状态。
- 输出可视化叠加检查图。

### M2：建筑与地标覆盖
- 把建筑组团拆成单栋 footprint。
- 用官方照片核验致远楼、笃行楼、图书馆、东大门等重点地标。
- 先完成所有建筑的 LOD1 体量，再逐步提高重点建筑细节。
- 不以程序化占位楼栋数量冒充真实建筑覆盖率。

### M3：统一像素美术与探索
- 建筑、道路、地面、树木、湖水、运动场采用统一像素艺术语言。
- 完成等距上帝视角、玩家移动、碰撞和建筑交互。
- 所有可探索对象读取同一份校园场景数据。

## 6. 当前代码基线与待替换项

- `src/data/campus/campusLayout.js`：已切换到 2026 级新生报到指南平面图的 1000×500 图像坐标基准，人工近似标注中央/西侧湖区、环湖路、校园连接道路、运动场及 53 个建筑轮廓候选。它们是像素场景空间骨架，不是测绘成果，也不代表学校建筑总数。
- `src/three/world/campus/createCampusScene.js`：像素校园主场景生成器，基于上述主空间底图生成建筑、湖区、环湖道路、运动场线、树木、花坛、长椅、路灯和玩家 Sprite。建筑视觉类型仍为程序化表达，具体楼栋名称、真实尺寸和外观尚待核验。
- `public/data/building-inventory-v1.json`：建筑候选台账，名称来源于公开资料，但位置、footprint、尺寸、层数多数尚未核验。
- `public/data/buildings.json`：正式 GLB 建筑资产清单目前为空，保持为空优于写入未经核实的模型定位数据。
- `src/three/engine/createCampusEngine.js`：默认直接启动像素校园，不再等待 GIS 场景接口或用 GIS 空数据替换主场景。

## 7. 当前阶段明确不做

- 不新增通用场景风格选择器。
- 不扩展通用 BIM/复杂屋顶参数化能力。
- 不为追求编辑器功能而继续扩大工具范围。
- 不把静态示意布局或程序化占位资产标记为真实校园。
- 不在空间底稿尚未可信前投入大规模精细建模。

## 7.1 2026-11-03 阶段调整

- 暂停室内建模、室内交互和楼层系统开发，不将其纳入当前迭代验收。
- 暂停 3D RPG 样板作为默认展示入口；默认回到 2D 校园平面图。
- 2D 图层当前仅绘制校园区域、水体、运动场、道路中心线和建筑 footprint；移除随机树木、随机花簇、虚构屋顶/窗户/立面等装饰，避免装饰掩盖空间数据质量。
- 已将 2026 级新生报到指南中的校园平面图登记为当前第一优先级参考源，来源日期 2026-08-28。
- 当前 53 个建筑候选、道路控制点和区域轮廓仍属于人工近似数字化，尚未完成逐栋/逐路段叠图复核；不得标记为测绘级真实数据。
- 后续先完成底图配准、校园边界、出入口、道路、水体、运动场和建筑 footprint 的叠图校准，再恢复 2.5D 表现。

## 8. 验收口径

- 全校主要空间分区和道路关系与参考平面图基本一致。
- 重要水体、运动场和出入口位置明确。
- 建筑逐栋拆分，有唯一 ID、来源和置信度。
- 像素风格统一，且不改变校园真实空间关系。
- 玩家能够在连续校园场景中探索，建筑碰撞和交互与场景数据一致。
- 对未核验内容明确标注，不宣称测绘级准确。
